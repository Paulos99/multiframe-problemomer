# Настройки сборки (только имена, значений здесь нет)

У Проблемомера нет серверных настроек: сайт статический. Все параметры задаются **при сборке** переменными окружения,
а значит попадают в готовые файлы и видны любому посетителю (в браузере). Секретов среди них нет и быть не должно:
не кладите сюда пароли и ключи с правами записи.

Образец — файл `.env.example` в корне репозитория (копируется в `.env`, который в репозиторий не попадает).

| Переменная | Обязательна | По умолчанию | Для чего |
|---|---|---|---|
| `VITE_BASE_PATH` | нет | `/problemomer/` | Путь на сайте |
| `VITE_SITE_URL` | нет | `https://stp-multiframe.ru/problemomer/` | Полный адрес для `canonical` и карточки в мессенджерах |
| `VITE_CALCULATOR_URL` | нет | `https://stp-multiframe.ru/calc/` | Ссылка калькулятора на кнопке и QR в PDF |
| `VITE_YM_ID` | нет | пусто | Номер счётчика Яндекс.Метрики. Пусто — Метрика и баннер cookies не включаются |
| `VITE_ANALYTICS_INGEST_URL` | нет | пусто | HTTPS-адрес приёма анонимных прохождений ([../analytics.md](../analytics.md)). Пусто — ничего не отправляется |

## Откуда берутся значения в готовом выпуске

Архив выпуска собирает GitHub (`release.yml`). Боевые значения подставляются из **секретов репозитория**
`PROD_VITE_YM_ID` и `PROD_VITE_ANALYTICS_INGEST_URL` (Settings → Secrets and variables → Actions). У проверочного стенда свои секреты
`VITE_YM_ID` и `VITE_ANALYTICS_INGEST_URL` (их использует `deploy.yml`): так проверки владельца не попадают в вашу статистику.

Команда размещения сообщает владельцу нужные значения (номер счётчика Метрики и адрес приёмника) безопасным каналом,
не в общем чате; владелец заносит их в секреты и выпускает новую метку. Если секреты пусты, сайт работает без Метрики
и без таблицы (баннер cookies тоже не появляется).

Альтернатива: собрать выпуск самим из метки (см. [BUILD.md](BUILD.md)) с вашими значениями в окружении.
