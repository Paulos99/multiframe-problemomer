# Выпуски: как владелец публикует версию и что получает команда

Боевой сайт обновляется **только** по метке выпуска `vX.Y.Z`, поставленной на проверенную версию ветки `main`.
Метка неизменяема: то, что вы установили, можно в любой момент установить снова или откатить.

## Что делает владелец (Павел)

1. Изменения вносятся через запрос на слияние (PR) в `main`. Проверки (`CI`: типы, тесты, акустика, сборка) должны быть зелёными.
2. После слияния стенд https://paulos99.github.io/multiframe-problemomer/ обновляется сам; владелец проверяет экраны.
3. Если стенд в порядке, на **ту же** версию `main` ставится метка:
   ```bash
   git checkout main && git pull
   git tag -a v1.0.0 -m "Что изменилось"
   git push origin v1.0.0
   ```
4. Рабочий процесс «Выпуск» (`.github/workflows/release.yml`; до переноса файл лежит в `deploy/github-workflows/`)
   проверяет, что метка лежит на `main`, повторяет проверки, собирает сайт под боевой адрес и публикует на странице
   [Releases](https://github.com/Paulos99/multiframe-problemomer/releases):
   - `problemomer-vX.Y.Z.zip` — готовая папка сайта (содержимое кладётся прямо в каталог сайта);
   - `problemomer-vX.Y.Z.zip.sha256` — контрольная сумма архива.
5. Владелец пишет команде: «Выпуск vX.Y.Z, контрольная сумма `…`, что изменилось, нужны ли действия».

Нумерация: `v1.0.1` — исправление, `v1.1.0` — новая возможность, `v2.0.0` — требует действий команды (например, новая настройка).

## Что делает команда

Ставит выпуск командой из [DEPLOY.md](DEPLOY.md): скрипт скачивает архив с GitHub, сверяет контрольную сумму (с опубликованной и,
если передать, с той, что владелец прислал отдельным сообщением), включает выпуск и проверяет `version.txt`. Откат — одной командой.

## Состав архива

Содержимое папки `dist/` + файл `version.txt` (номер выпуска). Сборка воспроизводима: из метки на Node 22 по `package-lock.json`
([BUILD.md](BUILD.md)). Исходный код и зависимости в архив не входят.

## Правила

- На боевой сервер ставятся только выпуски с метками на `main`. Ветки, архивы «из чата» и файлы, собранные не из метки, не ставятся.
- Новые настройки сборки владелец перечисляет в описании выпуска; значения для боевого сайта команда передаёт безопасным каналом
  ([ENV.md](ENV.md)).
- Правки кода на сервере и в репозитории не вносятся. Нашли ошибку — сообщите владельцу, он выпустит исправление.
- Репозиторий публичный: любой может прочитать код. Метки и ветку `main` защищает владелец (запрет удаления и перезаписи, метки `v*` только у владельца).

## Открытые вопросы перед первым выпуском

1. Номер первой метки (предложение: `v1.0.0`, как в `package.json`).
2. Боевой счётчик Метрики и адрес приёмника аналитики: заводит команда, значения идут в секреты `PROD_VITE_YM_ID` и
   `PROD_VITE_ANALYTICS_INGEST_URL`.
3. Контакт владельца для вопросов команды (в [README.md](README.md) оставлено место).
